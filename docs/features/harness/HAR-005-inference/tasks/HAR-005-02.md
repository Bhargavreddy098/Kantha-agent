# Task: HAR-005-02 — Tool-Capable Staging Smoke Test

### Task ID
`HAR-005-02`

### Objective
Create and execute an end-to-end staging smoke test validating a complete model turn with tool continuation, proving that tool call IDs, arguments, execution results, and attempt settlements correlate across multiple turns against a real or staged provider.

### Current implementation
- `HAR-005-01` delivers the live provider stream adapter.
- `HarnessRunner.execute` in `src/lib/harness/runner.ts` implements sequential tool batch dispatch, sibling skipping, and step continuation.
- In-process scripted scenarios exist in `src/lib/harness/scenario.ts`.

### Dependencies
- Prior task IDs: `HAR-005-01` (`DONE`).
- Required contracts: `IHarnessInference`, `IToolRegistry`, `IHarnessJournal` in `src/lib/harness/contracts.ts`.

### Expected files to change
- `scripts/smoke-tool-inference.mjs` — New smoke test script.
- `src/lib/harness/verify-inference.ts` — Staging verification helper for multi-turn tool calling.

### Implementation scope
1. Implement a 2-step tool execution smoke scenario:
   - Step 1: Model receives task, emits tool call `tool_read_file({ path: "README.md" })`.
   - Runner records intent, executes tool, captures bounded result, appends to history.
   - Step 2: Model receives tool result, generates concluding text response with `finishReason: "stop"`.
2. Validate that:
   - Tool `callId` emitted in Step 1 exactly matches the tool result ID submitted in Step 2 prompt history.
   - Two distinct physical provider attempts are reserved and settled in the Gateway ledger.
   - Journal records `tool_proposed`, `tool_result`, and `delta` events with gap-free sequences.
   - Final status is `completed` with correct diff digest and zero leaked attempts.

### Out of scope
- Multi-file repository patching (owned by `HAR-010`).
- Human approval workflows (owned by `HAR-012`).

### Invariants
- Each step must have a unique `attemptId`.
- No attempt reservation may remain unsettled at the end of the run.
- Completed tool results must never be executed a second time upon step continuation.

### Acceptance criteria
- [ ] 1. Multi-turn tool execution completes successfully through the real inference adapter.
- [ ] 2. Tool call ID remains invariant across tool proposal, dispatch, result, and subsequent model prompt.
- [ ] 3. Gateway ledger records exactly 2 attempts, both marked settled with valid token counts.
- [ ] 4. All assertions in `scripts/smoke-tool-inference.mjs` pass.

### Verification
```bash
node scripts/smoke-tool-inference.mjs
```
Expected output: 2-step run completes with status `completed`, 2 ledger attempts settled, exit code 0.
