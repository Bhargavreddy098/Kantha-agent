# Task: HAR-005-01 — Live Provider Adapter Qualification

### Task ID
`HAR-005-01`

### Parent feature
`HAR-005` — [SPEC.md](../SPEC.md)

### Objective
Wire the real provider dispatch adapter connecting `GatewayInference` to the AI SDK's `streamText` pipeline, normalizing live streaming chunks into `HarnessModelResponse` with buffered tool fragments, Zod schema validation, and per-attempt ledger reservation/settlement.

### Current implementation
- `src/lib/harness/inference.ts` has a fully tested `GatewayInference` class that consumes an injected `InferenceStreamSource` transport interface.
- In-memory mock tests in `scripts/test-h2-inference.mjs` pass 32 assertions proving reservation, budget refusal, retry on pre-output failure, chunk buffering, and settlement.
- A live adapter connecting `streamText` from `@ai-sdk/openai` / `@ai-sdk/anthropic` to `InferenceStreamSource` is outlined in `docs/harness/HANDOFF-H2.md` but not yet wired to real provider models.

### Dependencies
- Prior task IDs: None (H0–H1 baseline is complete; H2 fixture is complete).
- Required contracts: `IHarnessInference`, `HarnessModelRequest`, `HarnessModelResponse` in `src/lib/harness/contracts.ts`.

### Files to inspect
- `src/lib/harness/inference.ts` — `GatewayInference` implementation and `InferenceStreamSource` interface.
- `src/lib/gateway/server/chat-service.ts` — Existing provider streaming adapter using AI SDK `streamText`.
- `src/lib/gateway/providers/language-model.ts` — Gateway model resolution logic.
- `scripts/test-h2-inference.mjs` — Existing 32 assertions for the inference seam.

### Expected files to change
- `src/lib/harness/inference.ts` — Add live provider transport factory (`createLiveStreamSource` or equivalent).
- `src/lib/harness/create.ts` — Support electing between live provider and scripted inference based on environment/options.
- `scripts/test-live-inference-adapter.mjs` — New test script verifying the live adapter bridge.

### Implementation scope
1. Implement an `InferenceStreamSource` that wraps AI SDK `streamText`.
2. Map AI SDK stream events (`text-delta`, `tool-call`, `finish`) into `InferenceChunk`s (`text`, `tool_call_chunk`, `finish`).
3. Ensure tool-argument fragments are buffered and validated before emitting complete `HarnessToolCall` objects.
4. Pass through `AbortSignal` for clean mid-stream cancellation.
5. Verify that `UsageService.reserveAttempt` and `UsageService.settleAttempt` are called exactly once per physical attempt.

### Out of scope
- Live network calls to external paid APIs during automated CI (use mock AI SDK streams or local endpoint fixtures).
- Persistent hosting daemon setup (owned by `HAR-005-03`).
- Sandboxed tool execution (owned by `HAR-010`).

### Invariants
- Budget denial must result in zero outbound LLM requests.
- No partial or unvalidated tool calls may ever be returned in `HarnessModelResponse.toolCalls`.
- Every attempt must be settled with either exact token counts or an explicit `unknown` indicator.
- Gateway credentials must never leak into Harness data structures.

### Acceptance criteria
- [ ] 1. Live stream adapter maps `streamText` chunks into `InferenceChunk` stream without dropping text deltas.
- [ ] 2. Streamed tool argument JSON fragments are accumulated into complete strings and parsed cleanly.
- [ ] 3. Invalid tool JSON produces a typed error without throwing unhandled exceptions.
- [ ] 4. Cancellation via `AbortSignal` immediately stops the upstream stream and settles attempt as `cancelled`.
- [ ] 5. All existing 32 assertions in `scripts/test-h2-inference.mjs` continue to pass.
