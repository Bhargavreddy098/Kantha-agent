# Task: HAR-005-04 — Worker-Kill Reconciliation & Spend Audit

### Task ID
`HAR-005-04`

### Parent feature
`HAR-005` — [SPEC.md](../SPEC.md)

### Objective
Verify and harden the worker-kill reconciliation mechanism, proving that when a worker process is abruptly killed (`SIGKILL`) during an active LLM attempt or tool action, the subsequent recovery process reconciles ledger reservations to `unknown` usage without budget leaks or duplicate executions.

### Current implementation
- `GatewayInference` generates reservations with `UsageService.reserveAttempt`.
- If the node process crashes before `settleAttempt`, the database retains an open reservation.
- `UsageService` has reconciliation queries, but end-to-end failure injection under hard kill has not been automated.

### Dependencies
- Prior task IDs: `HAR-005-03` (`DONE`).
- Required contracts: `UsageService`, `GatewayDatabase`, `HarnessRunner` in contracts.

### Files to inspect
- `src/lib/gateway/server/usage-service.ts` — Attempt reservation and settlement ledger.
- `src/lib/harness/service.ts` — `recoverOpen` implementation.
- `src/lib/harness/runner.ts` — `resume()` method and action reconciliation.

### Expected files to change
- `src/lib/gateway/server/usage-service.ts` — Add reconciliation audit for abandoned attempt reservations.
- `src/lib/harness/service.ts` — Integrate usage reservation reconciliation into `recoverOpen()`.
- `scripts/test-worker-kill-reconciliation.mjs` — New failure injection test script.

### Implementation scope
1. Implement an automated failure-injection test:
   - Spawn a child process executing a long-running model turn.
   - Kill the child process with `process.kill(child.pid, 'SIGKILL')` while the reservation is active.
   - Start a recovery process.
2. Verify that:
   - The abandoned reservation is settled with status `unknown` and audited in the ledger.
   - No duplicate tool dispatch is triggered for in-flight actions lacking receipts.
   - Resuming the run issues a fresh attempt reservation with a new `attemptId`.
   - The total billed usage reflects exact known attempts plus audited unknown attempts.

### Out of scope
- Multi-region database replication failover.
- Third-party billing provider webhooks (e.g., Stripe).

### Invariants
- Abandoned attempt reservations must never remain permanently open in the ledger.
- A tool action without an authoritative receipt must never be re-executed automatically.

### Acceptance criteria
- [ ] 1. Hard process kill leaves a recoverable checkpoint and open reservation.
- [ ] 2. Recovery process settles open reservation as `unknown` with audit note.
- [ ] 3. Resumed execution continues cleanly or halts with a typed reconciliation error if action outcome is indeterminate.
- [ ] 4. All assertions in `scripts/test-worker-kill-reconciliation.mjs` pass.
