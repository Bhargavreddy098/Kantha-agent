# HAR-010-02 Ephemeral Git worktree adapter

**Status** PLANNED · [Feature spec](../SPEC.md) · [Predecessor handoff](../../../../handoffs/HAR-010-01.md)

## Outcome

Give the Harness a Git adapter that can create a run-owned worktree under `.gateway-data/workspaces/<runId>`, record the source checkout’s existing changes as `baselineEdits`, and clean up the worktree and temporary branch safely.

## Starting point and dependencies

- [HAR-010-01](HAR-010-01.md) has recorded fixture evidence. Check its completion and commit before using its contracts.
- Read the [sandbox strategy](../../../../technology/EXECUTION-SANDBOX.md#31-worktree-lifecycle-operations), [ADR-005](../../../../decisions/ADR-005-execution-sandbox-and-git-worktree.md) and the [workspace contract](../../../../harness/features/WORKSPACE.md).
## Reconciled Architecture Decisions (HAR-010-02)

1. **Branch Naming Standardization:**
   - Standard format: `kantha/run-${runId}`.
   - Identifier validation: `runId` must strictly match `/^[a-zA-Z0-9_-]{1,64}$/`. Traversal patterns (`..`, `/`, `\`) or invalid characters throw a typed `HarnessError('invalid_submission')`.
2. **`baselineEdits` Representation:**
   - Captured via `git status --porcelain=v1 -z -uall` against the source checkout before worktree creation.
   - Stored as a list of relative repository file paths (`string[]`) in `HarnessWorkspaceRef.baselineEdits`.
   - Handles paths with spaces, unicode characters, and renames without shell quoting errors.
3. **Workspace Integration & Candidate Digest:**
   - `baseRevision` is pinned to `git rev-parse HEAD` (or explicit submission commit SHA).
   - Candidate changes are calculated via `git diff ${baseRevision}` inside the isolated worktree.
   - `candidateDigest` is the SHA-256 hex hash of the candidate diff.
4. **Idempotent Cleanup:**
   - Worktree cleanup safely removes the registered worktree (`git worktree remove --force`), prunes remaining directory artifacts on disk if necessary, and deletes the temporary branch (`git branch -D`).
   - Re-running cleanup after partial failure converges safely without error.

## Scope

Implement worktree creation from a pinned revision, baseline metadata capture and repeatable cleanup using system Git. Expected additions are `src/lib/harness/sandbox/worktree.ts` and `scripts/test-kiri-worktree.mjs`. Inspect the existing Harness and sandbox contracts before editing.

Container execution, full baseline snapshot materialization, scoped read/search/patch and Harness wiring belong to their consuming slices.

## Acceptance criteria

- [ ] A disposable fixture repository yields a worktree at the expected run path on a temporary branch rooted at the requested revision.
- [ ] Baseline metadata records staged, unstaged and untracked changes in the fixture, including paths with spaces. Creating and cleaning up the worktree preserves the original checkout’s content, index and branch.
- [ ] Invalid paths and existing resources owned by another run are rejected before mutation.
- [ ] Cleanup removes the run-owned worktree and branch. Retrying after partial cleanup converges without changing unrelated worktrees or branches.
