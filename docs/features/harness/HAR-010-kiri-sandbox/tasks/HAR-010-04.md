# HAR-010-04 Harness workspace and sandbox integration

**Status** PLANNED · [Feature spec](../SPEC.md) · [Harness workspace contract](../../../../harness/features/WORKSPACE.md)

## Outcome

Connect the run-owned worktree and Kiri driver to one authorized Harness tool execution path. Verify the result and cleanup through the Harness entry point.

## Starting point and dependencies

- [HAR-010-02](HAR-010-02.md) provides the worktree lifecycle.
- [HAR-010-03](HAR-010-03.md) provides the container lifecycle.
- Confirm H2 release qualification in the [implementation order](../../../../roadmap/IMPLEMENTATION-ORDER.md#phase-complete-h2) and prepare a qualified Kiri runtime with the approved image.

## Scope

Inspect `src/lib/harness/contracts.ts`, `src/lib/harness/create.ts` and `src/lib/harness/runner.ts` for the workspace and dispatch boundaries. Wire one execution path through those boundaries. Add `scripts/test-kiri-sandbox-live.mjs` for a controlled repository fixture. Additional tool capabilities and release qualification remain separate roadmap work.

## Acceptance criteria

- [ ] An authorized fixture command produces a verifiable result in the isolated worktree while the original checkout stays intact.
- [ ] The live fixture verifies worktree-only access, bounded output and the absence of host data using harmless sentinel files.
- [ ] The Harness records durable intent before dispatch. An interrupted attempt is reconciled before any retry.
- [ ] Completion and interrupted-run recovery release the run-owned resources.

## Verification

```sh
node scripts/test-kiri-sandbox-live.mjs
node scripts/test-harness-fixtures.mjs
npx tsc --noEmit
```

The first script is a task deliverable and requires the qualified Kiri runtime. Record the runtime, image identity, exit codes and acceptance evidence in [the task handoff](../../../../handoffs/TEMPLATE.md).
