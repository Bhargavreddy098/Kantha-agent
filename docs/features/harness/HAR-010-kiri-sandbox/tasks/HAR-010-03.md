# HAR-010-03 Kiri Docker Engine API driver

**Status** PLANNED · [Feature spec](../SPEC.md) · [Kiri design and open decisions](../../../../specs/SPEC-kiri-sandbox.md)

## Outcome

Implement the Kiri driver against the sandbox interfaces so an isolated session can be created, used for a bounded command and torn down.

## Starting point and dependencies

- [HAR-010-01](HAR-010-01.md) provides the driver interface, path guard and output buffer.
- Confirm [ADR-006](../../../../decisions/ADR-006-kiri-microvm-execution-sandbox.md) and the design decisions affecting the driver, including image selection, socket configuration and behavior when Kiri is unavailable.

## Scope

Implement the Docker Engine API boundary in `src/lib/harness/sandbox/kiri-driver.ts`. Add driver tests using a controlled API double in `scripts/test-kiri-driver.mjs`. Keep Git worktree lifecycle in HAR-010-02 and live Harness integration in HAR-010-04.

## Acceptance criteria

- [ ] The driver uses the configured local socket or named pipe and reports an unavailable runtime through the sandbox interface.
- [ ] The create request mounts the validated worktree at `/workspace` and enforces the feature spec’s user, network, filesystem, capabilities and resource settings.
- [ ] Command success, nonzero exit and timeout produce bounded results under the sandbox contract.
- [ ] A failed startup and a repeated teardown leave no session owned by the test run.

## Verification

```sh
node scripts/test-kiri-driver.mjs
node scripts/test-kiri-sandbox-contracts.mjs
npx tsc --noEmit
```

The first script is a task deliverable. Record zero exit codes and acceptance results in [the task handoff](../../../../handoffs/TEMPLATE.md). Live runtime evidence belongs to HAR-010-04.
