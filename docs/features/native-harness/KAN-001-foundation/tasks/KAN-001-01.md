# Task: KAN-001-01 — Session Inbox & Idempotent Admission

**Status:** READY  
**Feature:** `KAN-001-foundation`  
**Parent Spec:** [SPEC-native-kantha-harness-architecture.md](../../../specs/SPEC-native-kantha-harness-architecture.md)

---

## 1. Objective

Implement the native Kantha Session Inbox subsystem (`session_inbox` SQLite table, prompt admission API, delivery modes `steer` vs `queue`, and idempotent submission).

This establishes the fundamental invariant: **Prompt admission precedes execution**. Submitting a prompt persists it to the inbox before the runner is awakened.

---

## 2. Requirements & Invariants

1. **Database Schema**:
   Create a migration / schema table `session_inbox` in SQLite:
   ```sql
   CREATE TABLE IF NOT EXISTS session_inbox (
     id TEXT PRIMARY KEY,
     session_id TEXT NOT NULL,
     request_id TEXT NOT NULL,
     status TEXT NOT NULL CHECK(status IN ('enqueued', 'delivered', 'cancelled')),
     delivery_mode TEXT NOT NULL CHECK(delivery_mode IN ('steer', 'queue')),
     text TEXT NOT NULL,
     attachments_json TEXT NOT NULL DEFAULT '[]',
     metadata_json TEXT NOT NULL DEFAULT '{}',
     enqueued_at TEXT NOT NULL,
     delivered_at TEXT,
     UNIQUE(session_id, request_id)
   );
   CREATE INDEX IF NOT EXISTS idx_session_inbox_pending 
     ON session_inbox (session_id, status, delivery_mode, enqueued_at);
   ```
2. **Idempotency**:
   - Submitting an enqueue request with the same `(session_id, request_id)` must return the existing inbox record with `idempotent: true` and must not duplicate rows or wake the runner multiple times.
3. **Delivery Modes**:
   - `steer`: Promoted and delivered at the next safe step boundary of an active turn.
   - `queue`: Delivered only when the session is completely idle.
4. **Clean Domain Interface**:
   Expose `ISessionInboxService` in `src/lib/harness/session-inbox.ts`:
   - `enqueuePrompt(input: EnqueuePromptInput): Promise<InboxItem>`
   - `getPendingItems(sessionId: string): Promise<InboxItem[]>`
   - `deliverNextItem(sessionId: string, mode: 'steer' | 'queue'): Promise<InboxItem | null>`
   - `cancelItem(inboxItemId: string): Promise<void>`
5. **No OpenCode Runtime Dependencies**:
   Written purely with native TypeScript and standard SQLite database drivers.

---

## 3. Implementation Plan

1. Create schema and queries in `src/lib/harness/session-inbox.ts`.
2. Connect to Kantha's existing SQLite database instance.
3. Implement `enqueuePrompt`, `getPendingItems`, `deliverNextItem`, and `cancelItem`.
4. Create test suite in `scripts/test-session-inbox.mjs` verifying:
   - Fresh prompt enqueue.
   - Idempotent deduplication on identical `(session_id, request_id)`.
   - `steer` vs `queue` delivery order.
   - Cancellation of pending items.
