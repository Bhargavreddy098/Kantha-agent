# Gateway implementation by agent

## Coordination

One integration owner assigns scope and lands shared changes. Each implementation agent gets one row below, its dependencies, [contracts](CONTRACTS.md), applicable [UI states](../frontend/README.md), and a declared file set. Use independent branches or worktrees when agents code in parallel. The contracts owner owns schemas and fixtures. The integration owner owns route composition, shared navigation and conflicts between slices. Review an incompatible contract change before consumers implement it.

Each handoff includes the behavior shipped, files touched, fixtures or migration impact, commands and results, and any remaining blocker. For user-facing work, include the browser path, a desktop and narrow-viewport capture, and the error or recovery state. Keep product UI and runtime implementation work tied to one observable flow per PR. The repository currently exposes `npm run lint` and `npm run build`. Record fixture and browser commands as they are established.

## Integration order

1. Land **01** and agree the shared request, error and event fixtures. Start **02**, **03** and **04** independently against fixtures. Review provider and chat flows before wiring them to the server. Start the usage contract from **04**'s attempt event shape and keep shared route edits with the integration owner.
2. Wire **02–04** into the current app and demonstrate one protected provider connection and a browser-streamed prompt locally or in isolated staging. Use fixtures for failure scenarios. The first demo is complete when an operator can configure, discover and select a model and a member can stream and stop a turn.
3. Integrate **05** and **06** in parallel once their required boundaries stabilize. Take live traffic after durable admission, authorized session recovery, egress policy and secret migration pass staging checks.
4. Add **07**, then verify **08** for the approved feature set. Keep shell, filesystem and MCP executors outside rollout until their own isolation, authorization and recovery are qualified. Scope **09** independently.

## First handoff

Assign **01** first. Ask for the route/caller inventory, typed fixtures, adapter interfaces and ownership map in one reviewable change. The first integration review uses a fixture connection with one eligible model, one successful chat stream, one cancelled stream and wrong-workspace cases. Once agreed, **02–04** can implement their isolated pieces.
